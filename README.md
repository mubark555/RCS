# ڤيوليت × سيم برايم — مركز القيادة الموحد

نظام إلكتروني موحّد لمتابعة مشاريع **سيم برايم** مع الشريك التشغيلي **ڤيوليت**.
بديل رقمي كامل عن ملف الإكسل — مبني بـ **Next.js** وقاعدة بيانات سحابية **Supabase**.

## المميزات

- **📊 لوحة مؤشرات:** نسبة الإنجاز، صحة المهام (سليمة / معرّضة للتعثر / متعثرة)، التقدّم حسب المشروع، ورسم بياني لتوزيع المهام، وسجل آخر الأنشطة.
- **📋 إدارة المهام:** إضافة/تعديل/حذف، بحث وفلترة حسب المشروع والحالة — بكل حقول الإكسل
  (النشاط، الأولوية، الحالة، المسؤول، الاستحقاق، بانتظار، العائق، حالة الاعتماد، الصحة، ملاحظات).
- **🎯 الأداء والمستهدفات (KPIs):** متابعة المؤشرات ومقارنتها بالمستهدفات حسب المشروع والرؤية.
- **📈 التقارير:** ملخّص شامل لأداء المشاريع والمستهدفات والمالية مع رسوم بيانية وتصدير Excel/طباعة.
- **💰 المالية:** فواتير **فيوليت ← سيم برايم** ومدفوعاتها (كامل/جزئي) والمقابل المرتبط بمؤشرات الأداء —
  بطاقات ملخّص ورسوم بيانية وتصدير. الوصول مقيّد بحسابات يعيّنها مالك النظام.
- **🔔 التنبيهات:** تنبيهات استحقاق تلقائية للمهام والاجتماعات والفواتير (قريبة/متأخرة) + إشعارات فورية وبريد.
- **🕓 سجل الأنشطة:** توثيق دائم لكل إضافة/تعديل/حذف داخل النظام — من نفّذها ومتى.
- **📅 جدولة الاجتماعات:** عنوان، تاريخ ووقت، مدة، مكان/رابط، حضور، جدول أعمال، حالة.
- **🗄️ أرشيف الملفات:** رفع الملفات وتصنيفها حسب المشروع/النوع، والاطلاع عليها وتنزيلها.
- **☁️ قاعدة بيانات مشتركة** عبر Supabase — يستخدمها الفريق كامل من أي جهاز.
- تم **نقل الـ 91 مهمة** من ملف الإكسل الأصلي كبيانات جاهزة.

## دورة العمل والاعتماد

`لم تبدأ` ← `قيد التنفيذ` ← `بانتظار مراجعة سيم` ← `معتمدة` (أو `مطلوب تعديل` فتعود للمسؤول مع الملاحظات).

- **ڤيوليت** تُعلن جاهزية التسليم (زر «جاهز للتسليم»)، و**سيم** تتخذ القرار من قسم **الاعتمادات** — كلٌّ مُسجَّل منفصلاً بالاسم والتاريخ.
- المدير يستطيع الاعتماد **نيابةً عن سيم** ويُوثَّق ذلك صراحةً في السجل.
- كل مهمة مرتبطة بمشروع و**مخرج** محدد، ولها نسبة إنجاز ومرفقات، وسبب التعليق/التأخير والجهة المطلوب منها الإجراء وموعد المعالجة.

## ترقية قاعدة بيانات قائمة (مرة واحدة لكل تحديث)

من Supabase → **SQL Editor** شغّل ملف الترحيل الجديد (آمن للتكرار ولا يحذف بيانات):

- `supabase/migrations/2026-09-batch1.sql` — دورة العمل والاعتماد، المخرجات، المرفقات، مزرعة قنيف.
- `supabase/migrations/2026-09-batch2.sql` — نطاق العمل، فترة ومصدر المؤشرات، مرفقات الفواتير والسداد.
- `supabase/migrations/2026-09-batch3.sql` — ربط المهام بمحضر الاجتماع.

## منع توقّف Supabase المجاني

`vercel.json` يشغّل `/api/keepalive` يومياً (Vercel Cron) باستعلام خفيف، حتى لا يتوقف المشروع المجاني بعد أسبوع بلا نشاط.

## وضعان للتشغيل

| الوضع | متى يعمل | الوصف |
| --- | --- | --- |
| **محلي (تجريبي)** | إذا لم تُضبط مفاتيح Supabase | يعمل فوراً، البيانات تُحفظ في متصفحك فقط (localStorage). مناسب للتجربة. |
| **سحابي** | عند ضبط مفاتيح Supabase | قاعدة بيانات وتخزين مشترك للفريق كامل. |

يظهر الوضع الحالي كشارة أعلى يمين الشاشة (◐ محلي / ☁ سحابي).

## التشغيل محلياً

```bash
npm install
npm run dev
```

ثم افتح <http://localhost:3000>. سيعمل مباشرة في الوضع المحلي التجريبي مع الـ 91 مهمة.

## ربط قاعدة البيانات السحابية (Supabase)

1. أنشئ مشروعاً مجانياً على [supabase.com](https://supabase.com).
2. من **SQL Editor** شغّل الملفين بالترتيب:
   - `supabase/schema.sql` (إنشاء الجداول + التخزين + الصلاحيات)
   - `supabase/seed.sql` (تعبئة الـ 91 مهمة)
3. من **Project Settings → API** انسخ:
   - `Project URL`
   - `anon public key`
4. أنشئ ملف `.env.local` (انسخ من `.env.example`):

   ```bash
   NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```

5. أعد التشغيل `npm run dev` — ستتحول الشارة إلى **☁ سحابي** ويشارك الفريق نفس البيانات.

> **ملاحظة أمان:** ملف `schema.sql` يضع سياسات وصول مفتوحة للبدء السريع. للاستخدام الحقيقي
> فعّل مصادقة Supabase (Auth) وقيّد السياسات حسب المستخدم.

## النشر على Vercel

1. ارفع المستودع إلى GitHub.
2. من [vercel.com](https://vercel.com) اختر **New Project** واربطه بالمستودع.
3. أضف متغيّري البيئة `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
4. اضغط **Deploy**.
