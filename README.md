# نظام إدارة مشروع سيم برايم (Seem Prime)

نظام إلكتروني متكامل لإدارة مشاريع ومهام المتعاقدين مع الشريك التشغيلي **فيوليت (Violet)**.
بديل رقمي كامل عن ملف الإكسل — مبني بـ **Next.js** وقاعدة بيانات سحابية **Supabase**.

## المميزات

- **📊 لوحة مؤشرات:** نسبة الإنجاز، صحة المهام (سليمة / معرّضة للتعثر / متعثرة)، التقدّم حسب المشروع.
- **📋 إدارة المهام:** إضافة/تعديل/حذف، بحث وفلترة حسب المشروع والحالة — بكل حقول الإكسل
  (النشاط، الأولوية، الحالة، المسؤول، الاستحقاق، بانتظار، العائق، حالة الاعتماد، الصحة، ملاحظات).
- **📅 جدولة الاجتماعات:** عنوان، تاريخ ووقت، مدة، مكان/رابط، حضور، جدول أعمال، حالة.
- **✉️ إشعارات البريد للاجتماعات:** دعوة عند الإنشاء (مع مرفق تقويم ICS ورابط Google Calendar)، إشعار عند التعديل
  يوضّح ما تغيّر، إشعار عند الإلغاء/الحذف، رسالة عند **إغلاق الاجتماع** تتضمن المحضر والقرارات (مع إبراز مهام كل مستلم)،
  و**تذكيرات تلقائية قبل الاجتماع** (10 د / 30 د / ساعة / 3 ساعات / يوم / يومين) — مع سجل إرسال لكل اجتماع.
- **🕒 سجل النشاط (للمدير):** متابعة دخول وخروج كل موظف يومياً (أول دخول، آخر خروج، مدة الاستخدام، متصل الآن)،
  وكل ما قام به: إضافة/تعديل/حذف/تغيير حالة المهام والاجتماعات والمشاريع والملفات — مع تفاصيل «من ← إلى» لكل حقل.
  فلترة باليوم والموظف ونوع النشاط وبحث نصي، وقائمة بالمهام التي عُدّلت، و**نظرة عامة** على آخر 7/30/90 يوماً
  (رسم للنشاط اليومي، ملخص لكل موظف: أيام الحضور، إجمالي ومتوسط الساعات، العمليات، المهام).
- **🗄️ أرشيف الملفات:** رفع الملفات وتصنيفها حسب المشروع/النوع، والاطلاع عليها وتنزيلها.
- **☁️ قاعدة بيانات مشتركة** عبر Supabase — يستخدمها الفريق كامل من أي جهاز.
- تم **نقل الـ 91 مهمة** من ملف الإكسل الأصلي كبيانات جاهزة.

## وضعان للتشغيل

| الوضع | متى يعمل | الوصف |
| --- | --- | --- |
| **محلي (تجريبي)** | إذا لم تُضبط مفاتيح Supabase | يعمل فوراً، البيانات تُحفظ في متصفحك فقط (localStorage). مناسب للتجربة. |
| **سحابي** | عند ضبط مفاتيح Supabase | قاعدة بيانات وتخزين مشترك للفريق كامل. |

يظهر الوضع الحالي كشارة أعلى يمين الشاشة (◐ محلي / ☁ سحابي).

## التشغيل محلياً

```bash
npm install
npm run dev
```

ثم افتح <http://localhost:3000>. سيعمل مباشرة في الوضع المحلي التجريبي مع الـ 91 مهمة.

## ربط قاعدة البيانات السحابية (Supabase)

1. أنشئ مشروعاً مجانياً على [supabase.com](https://supabase.com).
2. من **SQL Editor** شغّل الملفين بالترتيب:
   - `supabase/schema.sql` (إنشاء الجداول + التخزين + الصلاحيات)
   - `supabase/seed.sql` (تعبئة الـ 91 مهمة)
3. من **Project Settings → API** انسخ:
   - `Project URL`
   - `anon public key`
4. أنشئ ملف `.env.local` (انسخ من `.env.example`):

   ```bash
   NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```

5. أعد التشغيل `npm run dev` — ستتحول الشارة إلى **☁ سحابي** ويشارك الفريق نفس البيانات.

> **ملاحظة أمان:** ملف `schema.sql` يضع سياسات وصول مفتوحة للبدء السريع. للاستخدام الحقيقي
> فعّل مصادقة Supabase (Auth) وقيّد السياسات حسب المستخدم.

## تسجيل الدخول برمز OTP

عند ضبط `AUTH_SECRET` يصبح الدخول إلزامياً: يكتب الموظف بريده المسجّل في صفحة **الفريق**،
فيصله رمز من 6 أرقام (صالح 10 دقائق ولمرة واحدة)، ثم يدخل مباشرة بدون كلمة مرور.

| الإعداد | الوصف |
| --- | --- |
| `AUTH_SECRET` | مفتاح توقيع الجلسات (إلزامي لتفعيل الدخول) — `openssl rand -base64 32` |
| `AUTH_ADMIN_EMAILS` | بريد المدراء المسموح لهم دائماً (للبدء أول مرة) |
| `AUTH_SESSION_HOURS` | مدة الجلسة (افتراضياً 7 أيام مع «تذكّرني») |
| `SUPABASE_SERVICE_ROLE_KEY` | موصى به: لتتبّع محاولات الرمز في قاعدة البيانات (جدول `auth_otps`) |

الحماية: 5 محاولات لكل رمز، رمز جديد كل 60 ثانية وبحد 5 في الساعة، الرمز لا يُخزَّن (بصمة HMAC فقط)،
جلسة في كوكي `httpOnly`، وكل الصفحات وواجهات `/api` محمية. الموظف يرى النظام بصلاحياته فقط،
والمدير يستطيع «معاينة النظام كـ» أي مستخدم دون أن يتغيّر اسمه في سجل النشاط.

> ⚠️ سياسات Supabase في `schema.sql` ما زالت مفتوحة للمفتاح العام (anon)، أي أن من يملك المفتاح يستطيع
> الوصول للبيانات مباشرة متجاوزاً شاشة الدخول. للحماية الكاملة يجب نقل القراءة/الكتابة عبر الخادم أو
> تقييد السياسات (RLS) بحسب المستخدم.

## سجل النشاط والدخول والخروج

- يُسجَّل تلقائياً كل تعديل يتم عبر النظام باسم المستخدم المسجّل دخوله (أو المختار من «عرض النظام كـ» إن لم يُفعَّل الدخول).
- **الدخول:** عند فتح النظام أو اختيار مستخدم. **الخروج:** عند التبديل لمستخدم آخر، أو تلقائياً بعد 5 دقائق
  بلا نشاط (يظهر كـ«آخر ظهور»). يرسل النظام نبضاً كل دقيقة أثناء الاستخدام لحساب المدة بدقة.
- في الوضع السحابي شغّل `supabase/schema.sql` مجدداً لإنشاء الجدولين `activity_log` و `user_sessions`
  (سياسة السجل: إضافة وقراءة فقط — لا تعديل ولا حذف).

> لدقة كاملة في هوية الموظف فعّل **الدخول برمز OTP** (القسم السابق).

## إشعارات البريد الإلكتروني

### 1) إعداد المزوّد (متغيرات بيئة على الخادم — راجع `.env.example`)

| الخيار | المتغيرات |
| --- | --- |
| **Resend** (موصى به) | `RESEND_API_KEY`, `EMAIL_FROM` |
| **SMTP** (Gmail/Outlook/Zoho) | `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_FROM` |

اختياري: `APP_URL` (زر «فتح في النظام»)، `APP_TIMEZONE` (افتراضياً `Asia/Riyadh`)، `EMAIL_REPLY_TO`.

بعد الإعداد افتح **تخصيص النظام → إشعارات البريد** وأرسل **رسالة تجريبية**.
يصل البريد للحضور الذين لديهم بريد في صفحة **الفريق**، ولأي «بريد إضافي» في نموذج الاجتماع.

### 2) متى تُرسل الإشعارات؟

| الحدث | المحتوى |
| --- | --- |
| إنشاء اجتماع | دعوة + `invite.ics` + زر الانضمام + Google Calendar |
| تعديل الموعد/المكان/الحضور | ما الذي تغيّر + دعوة محدّثة (تُحدّث التقويم تلقائياً) |
| إلغاء / حذف | إشعار إلغاء + `cancel.ics` يحذف الحدث من التقويم |
| إغلاق الاجتماع (زر «إغلاق الاجتماع» أو الحالة «منتهي») | المحضر + القرارات والمهام (مع إبراز مهام المستلم) + الروابط |
| قبل الاجتماع | تذكيرات حسب الفترات المختارة لكل اجتماع |

كل حدث يمكن تفعيله/إيقافه من الإعدادات، وكل اجتماع له مفتاح تشغيل/إيقاف وسجل إرسال.

### 3) التذكيرات المجدولة (حتى لو لم يكن النظام مفتوحاً)

النظام يرسل التذكيرات تلقائياً أثناء فتحه في أي متصفح. ولضمانها دائماً (الوضع السحابي):

1. أضِف `CRON_SECRET` في Vercel (أي نص عشوائي طويل).
2. شغّل `supabase/schema.sql` مجدداً لإضافة أعمدة الإشعارات.
3. في GitHub → **Settings → Secrets and variables → Actions** أضِف `APP_URL` و `CRON_SECRET`.
   سيستدعي ملف `.github/workflows/meeting-reminders.yml` الرابط `/api/cron/reminders` كل 10 دقائق.

> بديل: أي خدمة cron خارجية (مثل cron-job.org) تستدعي
> `GET https://your-app/api/cron/reminders` مع الترويسة `Authorization: Bearer <CRON_SECRET>`.
> منع التكرار مضمون على الخادم، فلا يصل التذكير مرتين.

## النشر على Vercel

1. ارفع المستودع إلى GitHub.
2. من [vercel.com](https://vercel.com) اختر **New Project** واربطه بالمستودع.
3. أضف متغيّري البيئة `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   (ومتغيرات البريد أعلاه لتفعيل الإشعارات).
4. اضغط **Deploy**.

## بنية المشروع

```
app/
  page.js            لوحة المؤشرات
  tasks/page.js      إدارة المهام
  meetings/page.js   جدولة الاجتماعات
  archive/page.js    أرشيف الملفات
  activity/page.js   سجل النشاط والدخول والخروج
  login/page.js      تسجيل الدخول برمز OTP
  api/auth/*         طلب الرمز، التحقق، المستخدم الحالي، الخروج
middleware.js        حماية الصفحات والواجهات عند تفعيل الدخول
  api/notify         إرسال إشعارات البريد (POST) + حالة الإعداد (GET)
  api/cron/reminders التذكيرات المجدولة
  layout.js          الهيكل العام (RTL عربي) + التنقّل
  globals.css        التنسيق
components/           مكوّنات واجهة مشتركة (NavBar, Modal, Badge, TaskForm)
lib/
  supabase.js        عميل Supabase + كشف الوضع
  store.js           طبقة البيانات (سحابي / محلي)
  constants.js       القوائم والحالات والألوان
  seed-data.js       الـ 91 مهمة المستوردة من الإكسل
  activity.js        سجل النشاط + جلسات الدخول/الخروج
  notify-core.js     منطق الإشعارات المشترك (المستلمون، التذكيرات المستحقة)
  notifications.js   استدعاء الإشعارات من الواجهة
  server/            قوالب البريد + ICS + الإرسال (Resend/SMTP) — خادم فقط
supabase/
  schema.sql         مخطط قاعدة البيانات
  seed.sql           بيانات الـ 91 مهمة
scripts/
  generate-seed.mjs  أداة توليد seed.sql
```
