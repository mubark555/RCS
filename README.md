# نظام إدارة مشروع سيم برايم (Seem Prime)

نظام إلكتروني متكامل لإدارة مشاريع ومهام المتعاقدين مع الشريك التشغيلي **فيوليت (Violet)**.
بديل رقمي كامل عن ملف الإكسل — مبني بـ **Next.js** وقاعدة بيانات سحابية **Supabase**.

## المميزات

- **📊 لوحة مؤشرات:** نسبة الإنجاز، صحة المهام (سليمة / معرّضة للتعثر / متعثرة)، التقدّم حسب المشروع.
- **📋 إدارة المهام:** إضافة/تعديل/حذف، بحث وفلترة حسب المشروع والحالة — بكل حقول الإكسل
  (النشاط، الأولوية، الحالة، المسؤول، الاستحقاق، بانتظار، العائق، حالة الاعتماد، الصحة، ملاحظات).
- **📅 جدولة الاجتماعات:** عنوان، تاريخ ووقت، مدة، مكان/رابط، حضور، جدول أعمال، حالة.
- **🗄️ أرشيف الملفات:** رفع الملفات وتصنيفها حسب المشروع/النوع، والاطلاع عليها وتنزيلها.
- **☁️ قاعدة بيانات مشتركة** عبر Supabase — يستخدمها الفريق كامل من أي جهاز.
- تم **نقل الـ 91 مهمة** من ملف الإكسل الأصلي كبيانات جاهزة.

## وضعان للتشغيل

| الوضع | متى يعمل | الوصف |
| --- | --- | --- |
| **محلي (تجريبي)** | إذا لم تُضبط مفاتيح Supabase | يعمل فوراً، البيانات تُحفظ في متصفحك فقط (localStorage). مناسب للتجربة. |
| **سحابي** | عند ضبط مفاتيح Supabase | قاعدة بيانات وتخزين مشترك للفريق كامل. |

يظهر الوضع الحالي كشارة أعلى يمين الشاشة (◐ محلي / ☁ سحابي).

## التشغيل محلياً

```bash
npm install
npm run dev
```

ثم افتح <http://localhost:3000>. سيعمل مباشرة في الوضع المحلي التجريبي مع الـ 91 مهمة.

## ربط قاعدة البيانات السحابية (Supabase)

1. أنشئ مشروعاً مجانياً على [supabase.com](https://supabase.com).
2. من **SQL Editor** شغّل الملفات بالترتيب:
   - `supabase/schema.sql` (إنشاء الجداول + التخزين + الصلاحيات)
   - `supabase/seed.sql` (تعبئة الـ 91 مهمة)
   - كل ملفات `supabase/migrations/` بالترتيب (مطلوبة قبل نشر هذه النسخة من الواجهة — خذ نسخة احتياطية أولاً)
3. من **Project Settings → API** انسخ:
   - `Project URL`
   - `anon public key`
4. أنشئ ملف `.env.local` (انسخ من `.env.example`):

   ```bash
   NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```

5. أعد التشغيل `npm run dev` — ستتحول الشارة إلى **☁ سحابي** ويشارك الفريق نفس البيانات.

> **ملاحظة أمان:** ملف `schema.sql` يضع سياسات وصول مفتوحة للبدء السريع. للاستخدام الحقيقي
> فعّل مصادقة Supabase (Auth) وقيّد السياسات حسب المستخدم.

## سير عمل المهام

- الصفحة الرئيسية **«مهامي»** تعرض لكل مستخدم ما يتطلب إجراءً منه: المعادة للتعديل، المتأخرة، بانتظار مراجعته/موافقته/اعتماده، المستحقة اليوم، ثم القادمة وما ينتظر الآخرين، وإنجازاته المكتملة.
- لكل مهمة **مسار اعتماد** (تنفيذ فقط / مراجعة / اعتماد / مراجعة وموافقة / مسار كامل)، الافتراضي من إعداد المشروع.
- الحالة لا تُعدّل يدوياً؛ تتغير عبر الإجراءات (بدء، تسليم، قبول، طلب تعديل بملاحظات، إيقاف بسبب، استئناف، إعادة فتح للإدارة).
- المنفذ لا يراجع أو يعتمد عمله إلا بصلاحية صريحة من صفحة الفريق.
- في الوضع السحابي تُفرض القواعد في قاعدة البيانات عبر الدالة `task_transition` ومشغّل يمنع تغيير الحالة مباشرة.
- كل إجراء يُسجَّل في `task_events` (المستخدم، الإجراء، المرحلة، الملاحظة، الوقت) ويظهر في صفحة **سجل الإجراءات**.

## الصلاحيات وفصل المشاريع

- **الأدوار** (صفحة «الصلاحيات والوحدات»): مدير النظام، الإدارة العليا، مدير تشغيل، مدير وحدة، موظف، عميل — ويمكن إنشاء أدوار جديدة
  وتعديل صلاحيات كل دور من مصفوفة تغطي: الصفحات، نطاق البيانات، المهام، الاجتماعات والملفات، الإدارة، التقارير.
- **نطاق البيانات**: المستخدم يرى فقط المشاريع التي هو ضمن فريقها (مدير تشغيل / مدير مشروع / عضو / عميل) أو التابعة لوحدة يديرها،
  إلا إذا مُنح «الاطلاع على جميع المشاريع». المهام التي هو طرف فيها (منفذ/مراجع/معتمد) تظهر له دائماً.
- **دور المشروع**: مديرو التشغيل ومديرو المشروع يحصلون على صلاحيات إدارة المهام والاجتماعات والملفات **داخل مشروعهم فقط**.
- **الوحدات**: لكل وحدة مدير يرى كل مشاريعها؛ يُربط المشروع بوحدته من نموذج المشروع.
- **مراجعة الوصول**: جدول يوضح ما يراه كل مستخدم وما يملكه، ويكشف التعارضات (دور غير معرّف، موظف بلا مشاريع، عميل مضاف كعضو، أسماء لا تطابق مستخدمين…).
- الصفحات محمية من الفتح برابط مباشر، والبيانات محمية في قاعدة البيانات (ترحيل 002) بمجرد تفعيل `auth_required`.

## لوحة الإدارة والإشعارات

- **لوحة القيادة** (لمن يملك «مؤشرات لوحة القيادة»): المهام المفتوحة والمتأخرة، بانتظار المراجعة/الموافقة/الاعتماد،
  المتوقفة وأسبابها، توزيع المهام على الموظفين، حالة المشاريع (متأخر / يواجه عوائق / على المسار)، نسبة الالتزام بالمواعيد،
  والاجتماعات القادمة بتصنيف الحضور — كلها محسوبة من نطاق صلاحيات المستخدم فقط، مع تصدير CSV لمن يملك صلاحية التصدير.
- **الإشعارات** (الجرس أعلى الصفحة): إسناد مهمة، وصولها للمراجعة، طلب موافقة/اعتماد، إعادتها للتعديل مع الملاحظات،
  اعتمادها وإغلاقها، دعوات الاجتماعات (الإلزامي والأساسي افتراضياً)، تكليفات الاجتماعات، واقتراب الموعد أو تجاوزه.
  كل إشعار يفتح المهمة أو الاجتماع مباشرة، ولكل مستخدم تفضيلات لإيقاف ما لا يحتاجه.
- نسبة الالتزام بالمواعيد تُحسب للمهام المغلقة عبر سير العمل (التي لها تاريخ إغلاق)؛ المهام القديمة لا تدخل في الحساب.

## تسجيل الدخول

1. أنشئ حسابات الفريق من Supabase > Authentication > Users (بريد + كلمة مرور).
2. ضع البريد نفسه في ملف كل مستخدم من صفحة **الفريق** — يُربط الحساب تلقائياً عند أول دخول.
3. فعّل `NEXT_PUBLIC_AUTH_REQUIRED=true` وأعد النشر.
4. بعد التأكد من ربط الجميع (صفحة الفريق تُظهر «حساب دخول مرتبط»):
   `update public.app_config set value = 'true' where key = 'auth_required';`
   هذا يفعّل فصل الصلاحيات في قاعدة البيانات (RLS) ويمنع قبول هوية مرسلة من الواجهة دون جلسة دخول.

> قبل التفعيل يبقى خيار «عرض النظام كـ» للتجربة، ولا توجد هوية حقيقية.

## النشر على Vercel

1. ارفع المستودع إلى GitHub.
2. من [vercel.com](https://vercel.com) اختر **New Project** واربطه بالمستودع.
3. أضف متغيّري البيئة `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
4. اضغط **Deploy**.

## بنية المشروع

```
app/
  page.js            لوحة المؤشرات
  tasks/page.js      إدارة المهام
  meetings/page.js   جدولة الاجتماعات
  archive/page.js    أرشيف الملفات
  layout.js          الهيكل العام (RTL عربي) + التنقّل
  globals.css        التنسيق
components/           مكوّنات واجهة مشتركة (NavBar, Modal, Badge, TaskForm)
lib/
  supabase.js        عميل Supabase + كشف الوضع
  store.js           طبقة البيانات (سحابي / محلي)
  constants.js       القوائم والحالات والألوان
  seed-data.js       الـ 91 مهمة المستوردة من الإكسل
supabase/
  schema.sql         مخطط قاعدة البيانات
  seed.sql           بيانات الـ 91 مهمة
scripts/
  generate-seed.mjs  أداة توليد seed.sql
```
